======================================================================

Embedding service: Voyage AI

Embedding dimension: 1024

relevant evidence could be retrieved even when wording differed from the
query.

implemented the embedding pipeline using Voyage-3 (1024-dimensional

Voyage-4 series for the available free allowance, so migration to a

======================================================================
8. TECHNICAL DECISIONS
======================================================================

1.  Unified ingestion for supported text formats.
2.  300-character chunk overlap to preserve context.
3.  2500-character chunks to retain useful context for connected-fact
    questions.
4.  Semantic embeddings for meaning-based retrieval.
5.  Persistent local ChromaDB for reusable indexing.
6.  Source metadata preservation for evidence attribution.
7.  Separate indexing and runtime retrieval.

======================================================================
16. LIMITATIONS AND LESSONS
======================================================================

1.  Free LLM APIs have request quotas and rate limits.
2.  Free model availability can change.
3.  LLM/API failure should be distinguished from RAG/backend failure.
4.  PNG/JSON were not included in normal text extraction.
5.  Voyage-3 was used during development; Voyage-4 migration was
    identified as a deployment consideration.
6.  Robust retry/fallback handling is preferable to depending on a
    single free model.

Possible robust architecture: RAG | v LLM client | +–> OpenRouter free
model | +–> fallback provider/local model | v Final answer
